## The constraint

GitHub Pages for this repository is configured as a **project site deployed from the root of
`main`** — the legacy "deploy from a branch" mode. Two consequences follow, and they explain almost
everything unusual in this repo:

1. **GitHub does not run Vite.** It serves whatever files are in the branch. So the compiled
   `index.html`, `assets/` and `images/` must be committed.
2. **The site is served from a sub-path**, `https://zazieproductions.github.io/Mountain-Piper-website/`,
   not from a domain root. Every asset URL and router path must be prefixed with
   `/Mountain-Piper-website/`.

The alternative — switching to the "GitHub Actions" Pages source and deploying from an artefact —
would remove the committed build output entirely. It is a reasonable future change, but it means
moving off the branch model, so it has not been done.

## The pipeline

```
  git push origin main
          │
          ▼
┌──────────────────────────────────────────────────────────────┐
│ .github/workflows/publish-pages.yml                          │
│                                                              │
│   permissions: contents: write                               │
│   concurrency: publish-pages (cancel-in-progress)            │
│                                                              │
│   actions/checkout@v4                                        │
│   actions/setup-node@v4   node 22, npm cache                 │
│   npm ci                                                     │
│   npm run build:pages                                        │
│     ├── tsc -b                    typecheck                  │
│     ├── vite build --mode pages   base=/Mountain-Piper-website/│
│     └── node scripts/publish-github-pages.mjs                │
│                                                              │
│   git add assets images index.html 404.html .nojekyll \      │
│           favicon.svg robots.txt sitemap.xml                 │
│   git diff --cached --quiet                                  │
│     ├── no changes → "Published files already match"         │
│     └── changes    → commit "Publish static site …" + push   │
└──────────────────────────────────────────────────────────────┘
          │
          ▼
   GitHub Pages rebuilds and serves the site
```

### Why it does not loop

The bot's commit contains **only** generated paths. The workflow's trigger excludes exactly those:

```yaml
on:
  push:
    branches: [main]
    paths-ignore:
      - 'assets/**'
      - 'images/**'
      - 'index.html'
      - '404.html'
      - '.nojekyll'
      - 'favicon.svg'
      - 'robots.txt'
      - 'sitemap.xml'
```

So the commit does not retrigger the run. **If you add a new generated path, add it to
`paths-ignore` too** — otherwise the workflow will start looping.

The `git diff --cached --quiet` check means a push that produces no bundle change commits nothing.

## What the publish script does

`scripts/publish-github-pages.mjs` is ~50 lines and deliberately defensive.

**1. It refuses to publish a broken bundle.**

```js
if (!html.includes(`${pagesBase}assets/`)) {
  throw new Error(
    `Built HTML does not reference ${pagesBase}assets/. Refusing to publish a bundle that would load blank on GitHub Pages.`
  );
}
```

This is the single most important line in the deployment. A base-path regression produces a page
that returns `200`, renders an empty `<div id="root">`, and fails silently. This check turns that
into a red build.

**2. It rewrites the noscript navigation.** The static fallback links in `index.dev.html` are
root-absolute (`href="/weddings"`). The script rewrites them to the project sub-path so they work
when JavaScript is off.

**3. It stamps provenance** — a comment is injected after the doctype:

```html
<!-- Generated by npm run build:pages from index.dev.html. Do not edit by hand. -->
```

**4. It writes the artefacts:**

| Written | From |
|---|---|
| `index.html` | `dist/index.dev.html`, rewritten |
| `404.html` | Same content — this is what makes SPA deep links resolve on Pages |
| `.nojekyll` | Empty; disables Jekyll processing of `assets/` |
| `assets/` | `dist/assets/` (directory replaced wholesale) |
| `images/` | `dist/images/` (directory replaced wholesale) |
| `favicon.svg`, `robots.txt`, `sitemap.xml` | Copied from `dist/` |

Note that `index.html` and `404.html` are byte-identical. That is intentional and load-bearing:
GitHub Pages serves `404.html` for any unmatched path *with* a `404` status, so React Router boots,
reads the real pathname, and renders the right page.

## Deploying manually

You normally do not need to. If you do — for example to publish a hotfix without waiting for CI:

```bash
git checkout main && git pull
npm ci
npm run build:pages        # typecheck + build + write artefacts to the repo root
git status                 # review what changed
git add assets images index.html 404.html .nojekyll favicon.svg robots.txt sitemap.xml
git commit -m "Publish static site for GitHub Pages"
git push
```

> `npm run build:pages` rewrites files in your working tree. Never run it on a branch you do not
> intend to commit artefacts to.

## Continuous integration

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) is separate from the publish workflow and
**never writes to the repository** (`permissions: contents: read`). It runs on every pull request
and every push to `main`:

```
npm ci → npm run lint → npm run typecheck → npm run build → vite build --mode pages
                                                                     │
                                                                     ▼
                                          grep for /Mountain-Piper-website/assets/
                                          in dist-pages/index.dev.html
```

The last step is the same guard the publish script applies, moved earlier so a base-path regression
fails on the pull request instead of after it has been committed to `main`. The `pages` build is
uploaded as a workflow artefact (`pages-build`, retained 7 days) so a reviewer can inspect exactly
what would be published.

## Custom domain

`src/siteConfig.ts`, `sitemap.xml`, `robots.txt` and the static head in `index.dev.html` all
reference `https://mountainpiperavl.com`. The Pages URL is
`https://zazieproductions.github.io/Mountain-Piper-website/`.

To move the site onto the custom domain:

1. Add a `CNAME` file at the repository root containing `mountainpiperavl.com`, and have the publish
   script copy it alongside `favicon.svg`, `robots.txt` and `sitemap.xml` so it survives rebuilds.
2. Point DNS at GitHub Pages (an `A` record set, or a `CNAME` to
   `zazieproductions.github.io`).
3. In **Settings → Pages**, set the custom domain and enable HTTPS.
4. **Decide the base path.** A domain root means `pagesBase` should become `'/'` in both
   `vite.config.ts` and `scripts/publish-github-pages.mjs`. If you leave it at
   `/Mountain-Piper-website/`, every asset will 404.

The canonical URLs already point at `mountainpiperavl.com`, so step 4 is the one that matters.

## Alternative hosts

The build is a plain static bundle, so it can be hosted anywhere.

- **Netlify** — `public/_redirects` already contains SPA rewrites for every route. Build command
  `npm run build`, publish directory `dist`. Because the output entry is `dist/index.dev.html`,
  either rename it in a post-build step or set `build.rollupOptions.input` back to `index.html` for
  that host.
- **Vercel** — add a `vercel.json` rewrites entry mapping `/(.*)` to `/index.dev.html`, or apply the
  same rename.
- **Any static host** — copy `dist/` and configure a catch-all rewrite.

## Rolling back

The live site is whatever `main` last published, so a rollback is a revert:

```bash
git log --oneline -10                    # find the last good commit
git revert --no-edit <bad-sha>
git push
```

CI republishes automatically. Pages typically rebuilds within a minute or two; append
`?v=<anything>` to defeat CDN caching while you verify.

If the bad commit was the bot's publish commit, revert the *source* commit that triggered it —
otherwise the next push regenerates the same broken output.
